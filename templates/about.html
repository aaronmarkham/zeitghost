The data pipeline

Every hour, an ingest cycle pulls fresh news, analyzes it for political bias, generates left- and right-leaning rewrites of each story, and rebuilds this static site from the resulting memory store. Nothing in the pipeline is hidden — here's the whole flow:

NewsAPI                top-headlines + free-text query endpoints
   │                   (~50 articles per cycle, deduped against the shard store)
   ↓
trafilatura            fetches each article URL, extracts the cleaned body text
   │                   (used as Claude's input — never republished here, copyright)
   ↓
Claude Haiku 4.5       bias score (0=far left, 1=far right) + dual rewrites
   │                   (left-leaning + right-leaning framings of the same facts)
   ↓
spiritwriter shards    immutable, content-addressed records of the analysis
   │                   - zeitghost:article scope: full data + variants
   │                   - sw:article scope:        consumer-agnostic format
   ↓
Static site            re-rendered from the shard store each cycle
                       - home feed + per-source pages + per-article permalinks
                       - sparkline of bias drift over time
                       - client-side bias slider + date-range filter
{# ─── What's a shard ──────────────────────────────────────────────── #}

What's a shard?

A spiritwriter memory shard is the fundamental unit of persisted analysis. Each shard is:

  • Content-addressed — its shard_id is the hash of its contents. Identical content → identical id.
  • Immutable — once written, never modified. Updates create new shards.
  • A bundle of atoms — small typed key-value records (FACT, DECISION, CONTEXT, ...) that describe one thing.
  • Scoped — every shard belongs to exactly one scope (e.g. sw:article) so the store can answer "all article shards" in O(scope size) instead of O(everything).
  • Tagged — for cross-cutting filters (source:apnews, category:politics, month:2026-05).
  • Decay-classed — each shard has a TTL (article shards are STABLE = 90 days unless re-anchored).

Shards are general-purpose — anything atomic enough to live as a structured record fits the model. A few flavors to ground the idea:

A research note about a paper:

ShardAtom(kind=FACT,     key="paper_title",   value="Attention Is All You Need")
ShardAtom(kind=CONTEXT,  key="key_finding",   value="Self-attention beats RNNs on translation")
ShardAtom(kind=DECISION, key="cite_in_paper", value="true")

A personal preference an assistant should remember:

ShardAtom(kind=DECISION, key="coffee_order",   value="americano, oat milk, no sugar")
ShardAtom(kind=CONTEXT,  key="preferred_cafe", value="Blue Bottle, Mission")

An architectural decision in a software project:

ShardAtom(kind=DECISION, key="db_choice", value="postgres")
ShardAtom(kind=CONTEXT,  key="reason",    value="JSONB columns for typed sparse data")

And here's how this site uses them — a single article in the sw:article scope:

MemoryShard(
    scope="sw:article",
    shard_id="9a3f...",                # content hash
    parent_shard_id=null,              # set if this revises an earlier analysis
    origin="zeitghost",
    decay_class=STABLE,
    tags=["source:apnews", "category:politics", "month:2026-05"],
    meta={"entity_key": "article:b2c1...sha256...0e4a"},
    atoms=[
        ShardAtom(kind=FACT,     key="source_url",  value="https://..."),
        ShardAtom(kind=FACT,     key="title",       value="Senate passes bill..."),
        ShardAtom(kind=FACT,     key="summary",     value="A bipartisan bill..."),
        ShardAtom(kind=FACT,     key="source_name", value="AP News"),
        ShardAtom(kind=FACT,     key="published",   value="2026-05-09T14:30:00Z"),
        ShardAtom(kind=DECISION, key="bias_score",  value="0.50"),
        ShardAtom(kind=DECISION, key="bias_label",  value="center"),
    ],
)
{# ─── Two scopes ──────────────────────────────────────────────────── #}

Two scopes per article

Each ingested article is written into two shards in different scopes:

zeitghost:article
Full internal data — original title/summary, both L/R variants, bias score and label, analysis notes, and optional metadata. This is what powers the slider on the home page and the per-article permalink page.
sw:article
Consumer-agnostic format. Atom keys (title, summary, bias_score, ...) follow a stable convention so any spiritwriter-aware tool can read this site's data without knowing anything about zeitghost specifically.
{# ─── Lineage ─────────────────────────────────────────────────────── #}

Immutability and lineage

Shards are immutable — they're never modified after being written. When an article gets re-analyzed (better model, refetched body, prompt iteration), we don't overwrite the old shard. We write a new shard with parent_shard_id pointing back to its predecessor. That gives every article a queryable history:

  shard_id  parent_shard_id  origin       bias_score  created_at
  ────────  ───────────────  ───────────  ──────────  ────────────────────
  shard-A   ∅                zeitghost    0.65        2026-04-30T10:00:00Z   ← v1: first analysis
  shard-B   shard-A          zeitghost    0.71        2026-05-15T03:00:00Z   ← v2: re-analyzed with body
  shard-C   shard-B          zeitghost    0.69        2026-06-02T09:30:00Z   ← v3: prompt update

Reading the chain backward via parent_shard_id gives the full provenance — what we thought, when, and what changed. Reading forward shows the latest version. The old revisions don't disappear.

This matters for accountability. A bias-analysis site claiming "Source X is 0.72 right-leaning" should be auditable. With shard lineage you can ask: when did we first say that, what model produced it, has the score drifted as we refined our methodology?

Powered by spiritwriter

The shard format, lineage, decay TTLs, and content-addressing all come from spiritwriter — a library for building agents and applications around persistent, distributable memory. Because the sw:article atom keys follow a stable convention, any other spiritwriter-aware tool can read this site's data without needing to know anything about zeitghost specifically.
